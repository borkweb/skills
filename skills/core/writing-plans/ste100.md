# ASD-STE100 writing rules

ASD-STE100 Simplified Technical English (STE) is a controlled language for technical text. This file gives its writing rules in short form. It does not include the STE dictionary of approved words, so do not call the output "STE100 compliant." If a word is not a technical name, use the simplest common word that has one meaning.

## Do not change

Copy these exactly: code, commands, flags, paths, identifiers, error strings, direct quotations, frozen acceptance gates, names, numbers, units, dates and versions. Keep the headings, labels, status tokens and verdict tokens that another workflow requires. Keep requirement keywords (MUST, SHOULD, MAY) and their strength as written. Apply STE to the prose around them.

## Words

- Use one word for one meaning. Use the same word each time for the same thing. Do not change between "slice", "chunk" and "piece" for one concept.
- Technical names (products, components, APIs, domain terms) and technical verbs (deploy, merge, commit, rebase) are permitted.
- Use simple words. Do not use idioms, slang, metaphors or phrasal verbs when a single verb is available. For example, use "use" for "utilize" or "leverage", "before" for "prior to", "start" for "commence", "about" for "approximately", "make sure" for "ensure", "to" for "in order to", and "find" for "figure out".
- Use these verb forms only: imperative, infinitive, simple present, simple past and future ("will"). Use a past participle only as an adjective ("the changed file").
- Do not use perfect or progressive tenses. Write "The test failed", not "The test has been failing".
- Do not use "-ing" words, except as part of a technical name.
- Do not make a noun cluster of more than three words. Write "the timeout for webhook retries", not "webhook retry timeout value".
- Keep articles ("a", "an", "the") and "that". Do not remove words to make text shorter.

## Sentences

- Write a maximum of 20 words in a procedural sentence (an instruction or step). Write a maximum of 25 words in a descriptive sentence (an explanation, rationale or finding). A long literal does not get a word limit, but split the prose around it.
- Use the imperative for instructions: "Run the migration", not "The migration should be run".
- Write one instruction in each sentence, unless the actions occur at the same time.
- Put a condition before the instruction: "If the gate fails, stop the rollout."
- Use the active voice and name the actor. Use the passive only in descriptive text, and only when the actor is not known or not important.
- Write one idea in each sentence. Use connecting words ("then", "because", "but", "so") to show how sentences relate.
- Put the most important information first.
- Use a vertical list for steps in sequence or for three or more parallel items. Use a colon to start a list. Number the steps in order.

## Paragraphs and warnings

- Write one topic in each paragraph, with a maximum of six sentences. Start with the topic sentence.
- Start a warning or risk with a short command, then give the reason: "Do not run this on production. It deletes all rows."

## Punctuation

Do not use semicolons or em or en dashes (— –) to join two ideas. Write two sentences. Keep hyphens in compound words and flags.

## Check before you finish

- Count the words in each long sentence.
- Search for "-ing" words, "has been", "is being", semicolons, em or en dashes and the words in the substitution list above.
- Make sure that each literal is the same as its source.

## Example

Before: "We'll be leveraging the existing webhook retry queue infrastructure in order to ensure that failed deliveries are reattempted, which should mitigate most of the data loss we've been seeing."

After: "The design uses the current retry queue for webhooks. The queue sends each failed delivery again. This change will prevent most of the data loss."
