# Strategic scope review

## Expansion
Check the underlying demand, alternatives and constraints before proposing additional scope. State the concrete user benefit, new obligations, dependencies, cost and evidence needed for each expansion. Prioritize a few distinct options; no mandatory delight quota. Proposed features remain out of the implementation scope until accepted.

## Selective expansion
Keep the existing plan as the baseline. Identify only additions with a clear payoff for this goal, offer them separately and record accept/defer/reject. Accepted additions get explicit acceptance criteria; rejected ones do not reappear later.

## Hold
Assess whether the planned solution actually achieves the goal, whether existing code can be reused and where interfaces/failure paths need clarification. Do not add or remove features under the guise of rigor.

## Reduction
Find the smallest scope that still achieves the stated goal. Name what would be deferred and the resulting tradeoff. Preserve explicit must-haves and obtain a ruling for material scope reductions not already authorized.

## Longer-term consequences
When relevant, examine resource cost, migration burden, adoption assumptions, lock-in, operational ownership and conditions under which the choice should be revisited. Use measured evidence or label estimates. Avoid compulsory registries and diagrams that repeat the same decision.
